# O que pode ser automatizado na coleta de produtos, geração de links de afiliado, publicação de vídeos e conversão por DM sem violar termos ou sofrer bloqueios?

Fontes lidas em 2026-11-17 e atualizadas em 2026-11-24. Reverificar limites de API e políticas até 2027-02-24.

## Fatos observados por frente de automação

### 1. Coleta de produtos e geração de links de afiliados
- **Observação do projeto anterior (`~/Dev/vendas_online`) e dos pilotos `IBG-001` / `IBG-002` (`2026-11-24`):** consultas HTTP diretas a páginas de produto `/p/MLB...` no Mercado Livre acionam parede de verificação (*web-risk-verification* / *captcha*). Já o formulário oficial do afiliado autenticado (`https://www.mercadolivre.com.br/afiliados/linkbuilder`) opera normalmente em sessão persistente do Chrome (`--headless=new` com `User-Agent` padrão de Chrome desktop), convertendo anúncios elegíveis com estoque ativo em links curtos `https://meli.la/...` e recusando catálogos `/p/` sem oferta elegível ativa.
- **Mercado Livre Afiliados (API pública):** o programa opera via painel web oficial (`/l/afiliados-home` e `/afiliados/linkbuilder`), inexistindo endpoint público documentado de API para geração programática de links curtos `meli.la`. Fonte: [Programa de Afiliados Mercado Livre](https://www.mercadolivre.com.br/l/afiliados-home) *(lido em `2026-11-24`)*.
- **Amazon Associados (`Creators API` / `PA-API 5.0` e formato de URL):** o acesso à API oficial exige histórico mínimo de **3 vendas qualificadas nos primeiros 180 dias** e manutenção de vendas qualificadas em janela móvel, além de retornar `DetailPageURL` completo em vez de encurtador `amzn.to`. A construção parametrizada direta no formato `https://www.amazon.com.br/dp/<ASIN>/ref=nosim?tag=<ASSOCIATE_TAG>` é suportada pelas diretrizes do programa para contas com `Associate Tag` ativo. Fontes: [Acordo Operacional Amazon Associados](https://associados.amazon.com.br/help/operating/agreement) e [Documentação PA-API / Creators API](https://webservices.amazon.com/paapi5/documentation/) *(lidos em `2026-11-24`)*.

### 2. Publicação programática de vídeos nas redes sociais
- **YouTube Data API v3 (`videos.insert`):**
  - Opera em *bucket* dedicado de uploads de vídeo com custo de **1 unidade por chamada** e alocação padrão de **100 chamadas `videos.insert` por dia** por projeto Google Cloud. Fonte: [Quota Calculator — YouTube Data API v3](https://developers.google.com/youtube/v3/determine_quota_cost) *(lido em `2026-11-24`)*.
  - A restrição introduzida em 2020 que travava uploads de projetos não auditados em modo privado foi **removida pela Google**: a documentação oficial declara que vídeos enviados por projetos de API sem auditoria de conformidade podem ser publicados diretamente como `public` ou `unlisted`. Fontes: [Videos: insert — YouTube Data API](https://developers.google.com/youtube/v3/docs/videos/insert) e [Auditoria e Cotas da YouTube Data API](https://developers.google.com/youtube/data/guides/quota_and_compliance_audits) *(lidos em `2026-11-24`)*.
  - Suporta nativamente o campo booleano `status.containsSyntheticMedia` (declaração de mídia sintética/IA) e `status.selfDeclaredMadeForKids`, rejeitando colchetes angulares literais (`<` e `>`) em `snippet.title` e `snippet.description`. Fonte: [Videos: insert — YouTube Data API](https://developers.google.com/youtube/v3/docs/videos/insert) *(lido em `2026-11-24`)*.
  - Projetos Google Cloud cuja tela de consentimento OAuth permanece em status *"Testing"* expiram o `refresh_token` em **7 dias**; a publicação da tela de consentimento para uso próprio mantém o token ativo além dessa janela. Fonte: [Google Identity OAuth 2.0 Expiration](https://developers.google.com/identity/protocols/oauth2#expiration) *(lido em `2026-11-24`)*.
- **Instagram Graph API (`Content Publishing API`):**
  - Permite até **100 publicações a cada 24 horas** via contêiner assíncrono (`POST /<IG_ID>/media` com `media_type=REELS` e upload binário retomável em `rupload.facebook.com`, seguido de `POST /<IG_ID>/media_publish` quando `status_code=FINISHED`), operando para contas *Instagram Business* adicionadas como *Testers* enquanto o App Meta permanece em *Development Mode*. Fontes: [Content Publishing — Instagram Platform](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/content-publishing/) e [Resumable Upload — Reels](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media) *(lidos em `2026-11-24`)*.
  - **Três limites funcionais verificados na Graph API frente ao Meta Business Suite Web:** (a) elegibilidade à aba dedicada *Reels* documentada para durações entre **5 e 90 segundos** (enquanto a criação direta no Meta Business Suite / Instagram suporta Reels orgânicos de até 3 minutos — observado na interface oficial em `2026-11-24`); (b) ausência de parâmetro público documentado em `POST /<IG_ID>/media` para acionar o rótulo nativo *"AI info / Criado com IA"*; e (c) endpoints separados para Instagram Reels (`/<IG_ID>/media`) e Facebook Page Reels (`/<PAGE_ID>/video_reels`, conforme [Facebook Reels Publishing API](https://developers.facebook.com/docs/video-api/guides/reels-publishing/), lido em `2026-11-24`), enquanto o composer web publica simultaneamente nas duas contas vinculadas.
- **TikTok Content Posting API (`Direct Post`):**
  - Suporta nativamente o parâmetro booleano `"is_aigc": true` em `post_info` (`POST /v2/post/publish/video/init/`) para rotulagem automática de conteúdo gerado por IA, com limite de **6 inicializações por minuto** por `access_token`. Fonte: [Direct Post — TikTok Content Posting API](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post) *(lido em `2026-11-24`)*.
  - Aplicativos que ainda **não concluíram a auditoria formal de conformidade** no TikTok Developer Portal ficam restritos a `"privacy_level": "SELF_ONLY"` (modo privado, até 5 usuários/24h) e exigem que a própria conta criadora esteja configurada como privada durante o uso não auditado. Fonte: [Content Sharing Guidelines — TikTok](https://developers.tiktok.com/doc/content-sharing-guidelines) *(lido em `2026-11-24`)*.

### 3. Automação de comentários e mensagens diretas (Instagram DM)
- **Regras da plataforma via parceiro oficial (ManyChat) e Meta Business Suite:**
  - Exige conta Profissional vinculada a Página do Facebook e interação prévia do usuário (comentário, DM com palavra-chave ou resposta em Story), abrindo uma **janela de 24 horas** para envio de mensagens automatizadas. Fonte: [Regras de automação de DM no Instagram (ManyChat)](https://manychat.com/blog/instagram-dm-automation-rules/) *(lido em `2026-11-17`)*.
  - Relatos de comunidade indicam teto aproximado de **750 chamadas/hora** para respostas privadas — **não verificado** na documentação primária da Meta; relato em [Comunidade ManyChat](https://community.manychat.com/general-q-a-43/instagram-business-account-disabled-due-to-automation-10161) *(lido em `2026-11-17`)*.

### 4. Transporte de binários de vídeo no Git vs. GitHub Pages (`2026-11-24`)
- **Observação empírica nos pilotos `IBG-001` e `IBG-002` (`2026-11-24`):** empacotar arquivos `.mp4` renderizados (`30–75 MB` por produto) nos commits da branch `master` ocasionou erro `HTTP 408` no proxy HTTPS do GitHub na conexão residencial de teste (`~150–200 KiB/s`) e retardou a publicação de `vitrine/catalogo.json` (`~4 KB`). No workflow oficial de deploy customizado do GitHub Pages, o padrão recomendado pela documentação separa os jobs `build` (`actions/upload-pages-artifact`) e `deploy` (`needs: build`, `actions/deploy-pages`), com execução gratuita ilimitada de GitHub Actions e *GitHub Releases* (até `2 GiB` por arquivo anexado) em repositórios públicos. Fontes: [GitHub Pages Custom Workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) e [About GitHub Actions Billing](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions) *(lidos em `2026-11-24`)*.

## Inferências

- **Inferência:** No YouTube Shorts, a **YouTube Data API v3** elimina integralmente a dependência de seletores visuais de navegador sem exigir auditoria prévia para vídeos públicos e cobrindo `REQ-007` (`containsSyntheticMedia`).
- **Inferência:** No Instagram Reels e no TikTok, as restrições funcionais das APIs oficiais sem auditoria/paridade (teto de `90s` na aba Reels e ausência de flag `AI info` na Graph API; trava `SELF_ONLY` e conta privada obrigatória na TikTok API não auditada) justificam uma **arquitetura híbrida**: despachar via API HTTP oficial sempre que configurada e compatível com a duração/requisitos do episódio, mantendo o publicador local em perfil persistente do Chrome para episódios `> 90s`, postagem cruzada FB+IG com `REQ-007`, TikTok Studio e Linkbuilder do Mercado Livre.
- **Inferência:** Deslocar a geração/verificação de links `meli.la` para os Portões 1 e 3 (com trava determinística de `100%` antes do upload) e manter os `.mp4` fora da árvore Git eliminam o retrabalho pós-aprovação e os timeouts de rede na publicação da vitrine.
